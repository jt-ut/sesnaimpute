## Part A — one limit, three readers

`depth_grid._region_band_counts_fit`'s counts-based `F_50_REGION_MJY`/
`W_REGION_DEX` (absolute flux, complete low-column selection) is now the
only Spitzer fit: `depth_grid.build` writes it as a per-source product,
`catalog/sesna/limits_sesna_source__<R>.hdf5` (`F_LIM_50_MJY` (n,8), `W_DEX`
(8,), `F_50_REGION_MJY`, `ALPHA_REGION`, `DCOMP90_REF_LOG10` (8,),
`LIMIT_KIND` (8,)), and `catalog.limits.limits` now reads only that file —
confirmed by grep: no other module calls `product_path(..., "limits",
"source", ...)`, and `fittp/likelihood.py:303` reads `catalog_limits.limits`
exactly as before. `depths.py`'s Spitzer `DELTA_DEX` is now report-only
(one paragraph added to its docstring); its 2MASS `F50_2MASS_MJY`/
`WIDTH_DEX` are unchanged and still used. `depth_grid`'s per-pixel
`F_LIM_50_PIX_MJY` is now the pixel median of the same per-source array,
and `F_LIM_50_MED_MJY` is that identical array (the two datasets collapse,
per the brief) — `RUNBOOKtp.sh`'s `catalog.limits` comment updated; no line
move needed, `catalog.depth_grid` (line 121) already sits before every
`limits.limits` consumer.

## Part B — corrected: recovery curve is the diagnostic, not fit-vs-histogram

The coordinator's correction, implemented: the expected-vs-observed-count
form cannot see truncation (a histogram already cut off by another band's
requirement is itself well fit by a roll-off — confirmed on this data,
Perseus's I1 turnover 0.0293 mJy is 1.24× I2's 0.0236 mJy, the stellar
colour projected). The diagnostic is now the recovery curve itself
(already built for the substitution): for band `b`, band `r` most often
paired with it, `r`'s median colour on doubly-detected sources predicts
`b`'s flux for every `r`-measured source, and the fraction still carrying
`b`'s own detection is evaluated **at `b`'s own fitted `F_50`**
(`np.interp` on the binned curve). ≥0.9 there flags `LIMIT_KIND="bound"`;
`F_50` is replaced by the curve's 50% crossing, or the faintest ≥100-source
bin if the curve never drops below 90% down to it — same substitution rule
as before.

**One bug found and fixed while implementing this**: the crossing search
must itself require ≥100 sources per candidate bin (`MIN_RECOVERY_BIN_SOURCES`,
already used for the floor rule but not, until this fix, for the crossing
scan). Without it, a 2-source bin near the bright end (where the
colour-predicted-flux histogram thins out) can read 1-of-2 = 0.5 by pure
sampling noise and produce a nonsense "crossing" (Perseus I2 initially
came out at **56.8 mJy**, three decades brighter than any real source —
caught by inspection, not a subtle miss). Fixed by restricting both the
crossing search and the floor fallback to adequately-populated bins.
