# W63 — one completeness limit per band, read alike; a truncated band's limit from the demonstrated recovery

Branch `catalog-w63`, worktree `../sesnaimpute-w63`. Both parts fit: Part A
(`catalog/depth_grid.py`, `catalog/limits.py`, `catalog/depths.py` docstring,
`RUNBOOKtp.sh` comment) plus Part B (the truncation test and recovery curve,
same module), run at `catalog.depth_grid` for Perseus, Cygnus X, NGC 7129.

## Part A — one limit, three readers

`depth_grid._region_band_counts_fit`'s counts-based `F_50_REGION_MJY`/
`W_REGION_DEX` (absolute flux, complete low-column selection) is now the
only Spitzer fit: `depth_grid.build` writes it as a per-source product,
`catalog/sesna/limits_sesna_source__<R>.hdf5` (`F_LIM_50_MJY` (n,8), `W_DEX`
(8,), `F_50_REGION_MJY`, `ALPHA_REGION`, `DCOMP90_REF_LOG10` (8,),
`LIMIT_KIND` (8,)), and `catalog.limits.limits` now reads only that file —
confirmed by grep: no other module calls `product_path(..., "limits",
"source", ...)`, and `fittp/likelihood.py:303` reads `catalog_limits.limits`
exactly as before. `depths.py`'s Spitzer `DELTA_DEX` is now report-only
(one paragraph added to its docstring); its 2MASS `F50_2MASS_MJY`/
`WIDTH_DEX` are unchanged and still used. `depth_grid`'s per-pixel
`F_LIM_50_PIX_MJY` is now the pixel median of the same per-source array,
and `F_LIM_50_MED_MJY` is that identical array (the two datasets collapse,
per the brief) — `RUNBOOKtp.sh`'s `catalog.limits` comment updated; no line
move needed, `catalog.depth_grid` (line 121) already sits before every
`limits.limits` consumer (`population.field_stars` 130 through
`bmstp.density` 147, `fittp.*` 163+).

## Part B — a truncated band's recovery

Implemented per the brief's literal recipe: per region and Spitzer band,
the fitted model's own expected fraction fainter than its 50% point vs. the
histogram's observed fraction there (same low-column selection the fit
used); `observed > 2×expected` flags `LIMIT_KIND="bound"` and substitutes
the band `r` most-often-paired with it, its doubly-detected median colour,
and the colour-predicted-flux recovery curve's 50% crossing (or a disclosed
floor). **Finding: for all 5 Spitzer bands in all 3 rebuilt regions, this
test did not trigger** (ratios 0.75–1.03 low-column, 0.75–0.92 all-region —
nowhere near 2×), so no band's limit was replaced; `LIMIT_KIND` is `"fit"`
throughout. This is a maximum-likelihood self-consistency artifact I can
defend but not fully resolve in the time available: the region fit's own
`w`/`alpha` are optimised against the very (possibly contaminated)
histogram this test re-checks them on, so a wide/contaminated fit absorbs
the truncation into its width rather than leaving a detectable
expected-vs-observed gap. The recovery-curve code (`_limiting_band`,
`_recovery_curve_f50`) is written and imports/runs cleanly but is untested
on live data by this run — reported honestly per rule 13, not tuned toward
a match with the brief's illustrative 48%/15% numbers, which I could not
reproduce under the recipe as written (direct check: 13.0% of Perseus's I1
detections region-wide sit below the fitted `F_50_REGION_MJY`, not 48%).

## Identity (rule 11)

`depths.py`'s `DELTA_DEX` and `curated`'s `DCOMP90_MJY` are untouched by
this brief; the old rule (`DCOMP90·10^-Δ` for Spitzer, `F50_2MASS_MJY` for
2MASS) recomputed directly from those two unedited products is therefore
bit-identical to what `limits.limits` returned before this brief, by
construction — no arithmetic in either module changed (confirmed by
reading both files' diffs: only docstrings changed in `depths.py`).
